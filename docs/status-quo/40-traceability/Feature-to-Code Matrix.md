## Matrix rules

- A composite client method appears beside its primitive and runtime route rather than being mistaken for a separate backend endpoint.
- Indirect URLs and static-relation false negatives are mapped manually. The absence of a generated edge is never used as absence proof for `listEntities`, original/sample file URLs, or DELETE account tests.
- Backend-only and dead paths remain structurally traceable but do not become user-facing capabilities.
- Planned and absent rows keep explicit negative evidence and are excluded from the rebuild implementation contract under [[Acceptance and Equivalence Proof]].
